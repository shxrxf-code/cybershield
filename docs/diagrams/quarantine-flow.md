# Quarantine flow

Quarantine is **evidence storage, not execution**: bytes are written once
under an opaque server-generated key, read only through an integrity check
(SHA-256 over the stored blob), optionally AES-256-GCM-encrypted at rest, and
reaped after the retention window. Every byte read/release/delete is audited.
Code: `app/services/quarantine.py` and `app/api/routes/quarantine.py`.

```mermaid
sequenceDiagram
    autonumber
    participant C as Client
    participant R as routes /quarantine
    participant QS as QuarantineService
    participant CRYPTO as AES-256-GCM (CBSQ1)
    participant FS as storage_root/quarantine/
    participant DB as quarantine_items (+ access log)
    participant AU as audit_events

    Note over QS: write path (called from scan_service when request.quarantine)
    QS->>QS: enabled? · empty blob? → QuarantineError
    QS->>QS: storage_key = secrets.token_hex(24)
    %% ^ server-generated; a client filename is never used to build a path
    QS->>QS: safe_join(quarantine_dir, storage_key)
    alt QUARANTINE_ENCRYPTION_KEY set
        QS->>CRYPTO: derive_key(secret) · AESGCM.encrypt(nonce, data, AAD)
        CRYPTO-->>QS: CBSQ1 + nonce + ciphertext
    else plaintext mode (no key configured)
        Note over QS: documented plaintext fallback under private storage root
    end
    QS->>FS: write stored blob (mode wb)
    QS->>DB: insert QuarantineItem (hashes, integrity_hash, is_encrypted, expires=+14d)
    QS-->>R: storage_key + item

    Note over QS: read path — every read is verified then audited
    C->>R: GET /api/v1/quarantine/{id}/download (scope quarantine:read)
    R->>R: owner check (non-admin must own item, else 404)
    R->>QS: read_blob(item)
    QS->>FS: safe_join + read bytes
    QS->>QS: sha256(stored) == stored_integrity_hash?  else refuse (fail closed)
    alt item.is_encrypted and key set
        QS->>CRYPTO: AESGCM.decrypt(nonce, ciphertext, AAD)
        CRYPTO-->>QS: plaintext bytes
    end
    QS->>DB: quarantine_access_log(action=read)
    R-->>C: 200 bytes (sanitised filename in Content-Disposition)

    C->>R: POST /api/v1/quarantine/{id}/release (scope quarantine:write)
    R->>QS: release(item)
    %% ^ read_blob (integrity check) + mark is_released · released_at
    QS->>DB: access_log(action=release)
    AU->>AU: audit quarantine.release
    R-->>C: 200 verified bytes

    C->>R: DELETE /api/v1/quarantine/{id} (scope quarantine:write)
    R->>QS: delete(item)
    QS->>FS: safe_join + unlink(missing_ok=True)
    QS->>DB: access_log(action=delete) · delete row
    AU->>AU: audit quarantine.delete
    R-->>C: 204

    Note over QS: reaping (housekeeping)
    QS->>DB: select rows where expires_at <= now
    QS->>FS: unlink each expired blob
    QS->>DB: access_log(action=reap) · delete rows
```

Diagrams the guarantees in words:

- The **client filename never becomes a path**: `storage_key` is generated by
  the server and every access re-checks `safe_join` containment.
- A blob modified outside this service fails the stored-SHA256 check **before**
  decryption (fail-closed); an encrypted blob with no key configured is refused,
  never plaintext-degraded.
- `quarantine:read` governs download; `quarantine:write` governs release and
  delete; both require ownership unless the principal is an administrator.
